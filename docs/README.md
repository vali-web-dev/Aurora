## 🔧 Technical Access

### Browser
Visit `/docs/` to browse all documentation in your browser with full formatting.

Examples:
- `/docs/aurora-book/end-user/start-here`
- `/docs/aurora-book/end-user/universes`
- `/docs/aurora-book/developer/architecture`

### In-App
Open the DocsPortal using:
- Menu → Help → Documentation
- Keyboard shortcut: `Cmd+?` or `Ctrl+?`
- Voice: Ask Companion: "Show documentation"

### Local Files
All documentation is markdown. Access directly:
```bash
cd docs/aurora-book/end-user
cat start-here.md
```

- **HTML** — Full formatting (from browser)

## 🤝 Contributing

We welcome documentation contributions!

### How to Contribute

1. **Read** the [Contributing Guidelines](/docs/aurora-book/developer/contributing)
2. **Follow** the chapter structure:
   - YAML front matter with metadata
   - "How To" section with workflow steps
   - "Common Workflows" section (3-5 per universe)
   - Visual callouts for UI screenshots
3. **Test** links in `/docs/` route
4. **Submit** a pull request

### Recognition
Contributors are recognized in:
- PUBLICATION_APPENDIX.md (Contributor Acknowledgments)
- GitHub repository (Co-authors)
- Community channels (Featured)

## 📝 Content Guidelines

### Workflows
Each workflow should follow this pattern:
```markdown
## Workflow: [Task Name]

**Steps:**
1. [Action with location]
2. [Action with confirmation]
3. [Result/next step]

**Expected outcome**: [What should happen]
**Related workflows**: [Links to similar tasks]
```

### Screenshots/Callouts
Use this format for visual descriptions:
```markdown
## Visual Guide

**[Screen Name]**
> [Description of what user sees, key UI elements, where to find things]
```

### Cross-Universe Integration
When a workflow touches multiple universes, link to them:
```markdown
**Integration**: This workflow connects...
- [Universe 1](/docs/aurora-book/end-user/universes/XX-name)
- [Universe 2](/docs/aurora-book/end-user/universes/XX-name)
```

## 🐛 Reporting Issues

Found an error or broken link?

1. **Check** if link is correct format (e.g., `/docs/path`, not `docs/path.md`)
2. **Report** in GitHub Issues with:
   - URL where you found the issue
   - What you expected to see
   - What you actually saw
3. **Follow** the issue template
